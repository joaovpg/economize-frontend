# Integração tipada por serviços e contrato HTTP compartilhado

**Status:** Superseded by [ADR-0008](0008-integracao-do-tanstack-query-com-o-tanstack-router.md)

As integrações HTTP existentes serão centralizadas em serviços por domínio, mantendo o cliente Ky como infraestrutura compartilhada e os loaders do TanStack Router como mecanismo de carregamento nesta etapa. Requests e responses serão validados por schemas Zod, com tipos inferidos; erros serão normalizados em `ApiError` a partir do Problem Details do backend, incluindo erros HTTP, de rede, timeout e contrato, enquanto cancelamentos permanecerão cancelamentos. Esta ADR registra o desenho de serviços anterior à adoção do TanStack Query; a integração atual está definida pela ADR-0008.

O escopo inicial fica limitado às integrações de autenticação, contas e categorias. A consulta de transações foi incorporada posteriormente conforme [ADR-0007](0007-consulta-de-transacoes-integrada.md); o resumo continua sem integração própria enquanto não houver uma rota correspondente no backend. Os nomes das operações dos serviços seguirão o domínio e a rota HTTP para facilitar comparação com o Swagger, como `postLogin`, `getCategorias` e `getTransacoes`, mesmo que isso seja menos abstrato que nomes puramente orientados a caso de uso. A decisão original de manter loaders como único mecanismo de carregamento foi substituída pela ADR-0008; a separação entre serviços e transporte continua válida.

Retries permanecerão conservadores para leituras e operações idempotentes, sem retry automático cego para `POST`. O cliente usará `credentials: "include"` para enviar cookies automaticamente, mas não tentará ler cookies no JavaScript nem inferir `X-CSRF-Token`. Antes de adicionar operações mutáveis, o backend e o frontend deverão definir um canal explícito para entrega do token CSRF; o escopo atual contém apenas login público e leituras.
